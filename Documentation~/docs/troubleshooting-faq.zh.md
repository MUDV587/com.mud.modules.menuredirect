# 故障排查与 FAQ

## 新菜单没有出现

1. 检查 Console 是否有编译错误。
2. 等待编译和域重载完成。
3. 确认生成文件存在于配置目录。
4. 打开设置页再次点击 **应用**。
5. 确认规则已启用且通过验证。

如果包装代码有变化，原菜单会在重载后才隐藏。编译期间原菜单可能仍然可见。

## 原菜单仍然可见

- 生成代码可能过期或缺失；编译成功后重新应用。
- 规则可能未启用或验证失败。
- 其它包可能在工具隐藏后重新注册了菜单。
- 包装不可用时发生域重载，Bootstrap 会有意暂缓隐藏。

查看反馈区中的生成代码状态。

## 原菜单和新菜单都不见了

正常情况下不应发生，因为隐藏会等待包装就绪。如果出现：

1. 检查 Console 编译错误。
2. 确认 `MenuRedirects.g.cs` 存在且带生成头。
3. 修复编译错误。
4. 再次点击 **应用**。
5. 必要时删除生成文件，让下一次域重载恢复原菜单。

## 应用按钮禁用

规则存在验证错误。打开详情面板查看验证结果。
常见原因包括目标路径已存在、原路径无效、规则重叠或菜单受保护。

警告不会禁用应用。

## 菜单选择器为空或缺少条目

- 动态菜单不在注册表中，请手动输入路径。
- 点击选择器中的刷新按钮。
- 菜单可能来自尚未加载的包，等待编译完成。
- 受保护条目会显示但不可选。

## 快捷键丢失

快捷键是编译期 `[MenuItem]` 特性，不会复制到生成包装。
请手动为新菜单添加快捷键。应用反馈会列出受影响的快捷键。

## 目标路径已存在

选择其它目标、先隐藏已有目标，或删除冲突规则。工具不会覆盖已有菜单。

## 切换语言后没有其它变化

这是预期行为。语言按项目保存在 `EditorPrefs`，不会标记未保存、保存配置或重新编译生成代码。

## 可以重定向动态注册的菜单吗？

不可以。动态菜单可以隐藏，但重定向需要静态 `[MenuItem]` 方法才能生成包装。
请改为静态特性，或使用仅隐藏。

## 配置可以提交到版本库吗？

可以。提交：

```text
ProjectSettings/MenuRedirect.asset
Assets/MenuRedirects/Editor/MenuRedirects.g.cs
```

不要提交 `Library/MenuRedirectDraft.json`。

## 团队可以使用不同的菜单布局吗？

配置是项目级的。不同布局需要不同分支或项目。语言偏好是本机按用户保存的。

## 会在运行时构建中生效吗？

不会。它是纯编辑器包，只修改编辑器菜单。

## 会修改第三方包吗？

不会。它只读取菜单注册表，并在 `Assets` 下生成独立文件；
不会修改第三方源码、资产、asmdef 或包清单。

## 如何彻底移除？

卸载前先执行清理命令，然后移除包。详见[清理与卸载](cleanup.md)。

## 仍然无法解决？

提交 issue 时请附上：

- Unity 版本；
- 包版本；
- 规则和验证面板截图；
- 相关 Console 错误；
- 生成文件是否存在、是否与配置目录一致。
