# 应用、生成代码与域重载

Menu Redirect 由两部分协同工作：生成的包装代码和被隐藏的原菜单。执行顺序很重要。

## 应用顺序

点击 **应用** 后，工具会：

1. 验证规则；
2. 写入新的生成包装文件；
3. 保存 `ProjectSettings/MenuRedirect.asset`；
4. 如果生成目录变化，删除旧文件；
5. 如果包装代码没有变化，立即隐藏原菜单；如果有变化，则等待编译和域重载完成后再隐藏。

如果保存配置失败，刚写入的包装文件会回滚。如果旧文件删除失败，新文件会被撤销，
路径指回旧文件。

## 生成代码

默认位置：

```text
Assets/MenuRedirects/Editor/MenuRedirects.g.cs
```

目录可以在设置页修改，但必须满足：

- 文件名固定为 `MenuRedirects.g.cs`；
- 目录位于 `Assets` 下；
- 路径中包含名为 `Editor` 的目录。

文件首行带本工具生成头。只有带该头部的文件才会被覆盖、迁移或删除。

每条启用规则生成一个 `[MenuItem(新路径)]` 包装，内部调用
`MenuRedirectInvoker.Execute(原路径)`，通过反射执行原始 `[MenuItem]` 方法。
原方法带 validate 时，也会生成验证包装。

这里不使用 `EditorApplication.ExecuteMenuItem`：原菜单移除后它会返回 `false`。

## 为什么隐藏要等待域重载

如果包装代码有变化，新菜单要等 Unity 编译并完成域重载后才注册。
如果在此之前隐藏原菜单，就会出现新旧入口都不存在的空档。

Bootstrap 会在重载后确认生成文件存在且与当前规则一致，再重放隐藏。
如果编译失败或文件缺失，则暂缓隐藏。

## 域重载后的重放

每次域重载后，`MenuRedirectBootstrap` 都会检查配置和生成代码。
如果包装已就绪，它再次移除原菜单。

这是必要的，因为 Unity 每次重载都会重建菜单注册表，移除操作本身不会永久保留。

## 生成代码过期或缺失

以下情况会跳过隐藏：

- 生成文件缺失；
- 生成头缺失；
- 生成内容与当前规则不一致；
- 工程存在编译错误，导致包装无法加载。

修复编译错误后再次点击 **应用**。反馈区会说明缺失内容。

## 多个生成文件

如果工程中存在多个带本工具生成头的 `MenuRedirects.g.cs`，应用会中止。
多个文件会产生重复的菜单类。删除多余文件后重新应用。

## 手动修改

不要手动编辑 `MenuRedirects.g.cs`，下次应用会覆盖。请修改设置页中的规则。

## 快捷键注释

当包装替换的菜单带快捷键时，生成文件会在受影响方法前写入注释。
应用反馈也会列出快捷键数量和按键。快捷键需要手动添加到新菜单。

## 还原

**还原** 只丢弃未保存的内存修改。它不会改变已保存配置、生成代码，
也不会恢复当前会话中已经隐藏的菜单。要恢复本次会话移除的菜单，需要一次域重载。
